## Pattern: OpenCode V2 dual-support plugin entrypoint

**Context**: V2 makes the plugin API an intentional breaking change — V1 plugin implementations do not run in V2. This repo's local plugins deploy as bare `.ts` files into `~/.config/opencode/plugins/` with no node_modules.
**Pattern**: One file serves both runtimes via a default export object: `{ id, setup(ctx), server(input) }`. V2 reads `id` + `setup(ctx)`; V1 (>= 1.18.29) calls `server()`. Do NOT statically `import { Plugin } from "@opencode/plugin"` — the docs describe it as a typing helper, and the import would not resolve in deployed bare-`.ts` context (nor under V1). Hook mapping: `experimental.chat.system.transform` → `ctx.session.hook("context")` (edit `event.system`); `tool.execute.before` → `ctx.tool.hook("execute.before")` (single mutable `event`, not `(input, output)`); `chat.message` → `ctx.session.hook("prompt")`; `config`/`command.execute.before` → `ctx.command.transform`. Config: `subagent_depth` must move to `experimental.subagent_depth` (V2 accepts-but-ignores the top-level key).
**Rationale**: Template deploys to machines that may run V1 or V2; per-runsource forks would drift. Dual entrypoint is the docs' own recommendation for packages supporting both.
**Alternatives Considered**: V2-only port — breaks V1 < 1.18.29 deploy targets with no error. Rejected for a template repo.
**Trade-offs**: `agent: "build"` pin on plugin slash commands has no documented V2 CommandDefinition equivalent (V2 commands run in the session's active agent). V2 logging uses `console` (no documented `ctx.app.log`). npm plugins (11 pins) are still V1-era and inert under V2 until each ships a V2/dual build.

**Addendum (2026-09-13, MCP):** V2 does NOT normalize the V1 `mcp.<name>` shape — `mcp.servers.<name>` is required and wrong-shape entries are silently ignored (`opencode mcp list` → "No MCP servers configured" despite entries present). The enable flag inverts: `enabled: false` → `disabled: true` (absence = enabled). Bigger trap: a higher-precedence project config REPLACES the whole server object, so per-project opt-in snippets must repeat the full type/command definition (the old `{"mcp":{"atlassian":{"enabled":true}}}` one-liner pattern is dead). Sync surfaces: `opencode_app/opencode.json`, all `deploy/packs/pack-*.json`, `deploy/merge-packs.mjs` (dry-run report key `p.mcp?.servers`), setup.sh/ps1 help text, repo-setup/ticket/markitdown/docling/nextjs/autodesk skills, office-document agent, README/MIGRATION/deploy-.AGENTS.md snippets, and 3 bats test files.

Sync surfaces beyond the config: `deploy/apply-skill-profile.mjs` + `init.mjs` + `resolve-models.mjs` + `build-registry.mjs` (frontmatter parser now handles flow-map rule lists), all 6 `deploy/packs/*.json`, setup.sh/ps1, 7 bats files, README/MIGRATION/AGENTS/deploy-.AGENTS.md, 8 skill docs, 9 agent body docs.
