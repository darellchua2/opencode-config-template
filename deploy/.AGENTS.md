# OpenCode Configuration

User-level instructions injected into every opencode session (primary + inherited subagents). Terse by design: opencode's own agent picker, `description` frontmatter, and `available_skills` listing already surface *which* agents/skills exist and their triggers — this file encodes only rules the model would get wrong without them.

## Task Delegation Order

1. **Subagents first** — delegate to the specialized subagent whose `description` matches the task (opencode lists them); use the Task tool. Fall back to built-in `general` for multi-step/parallel work and built-in `explore` for read-only codebase search.
2. **Skills second** — load via the Skill tool only when no subagent fits.
3. **Direct last** — trivial tasks or explicit user request only.

**Skill vs subagent decision:** load a skill directly when you need *knowledge/procedure* to apply in your own context (commit formatting, a decision tree, a checklist); spawn a subagent when the *work itself* would flood your context (reading many files, long tool-call chains) or needs a fresh window + specialized permissions. Rule of thumb — **skill = knowledge you lack; subagent = context you want to protect.**

**Non-obvious routing exceptions** (the model would default wrong without these):
- OpenAPI contract review / breaking-change detection: **no subagent** — load `openapi-contract-adherence-skill` directly when trigger phrases appear ("openapi diff", "api contract", "breaking change", "consumer update plan", "spec changed").
- Image / screenshot / PDF / non-text content: the primary session is **text-only** and will hallucinate visual detail — always delegate analysis to `image-analyzer-subagent`.

## MCP Tool Routing

- **Web fetch:** use built-in `webfetch` first; fall back to `zai-web-reader` only on failure (>5MB, timeout, encoding).
- **Local files:** always use built-in `Read` for local/`file://` paths. Never use MCP resource tools (`read_mcp_resource`, `list_mcp_resources`, `list_mcp_resource_templates`) for local files — those are for MCP server resources (DB schemas, APIs) only. Do not configure the `filesystem` MCP server; it is redundant with `Read`/`glob`/`grep` and causes tool-selection ambiguity.
- **Document → Markdown extraction:** when an agent encounters a `.docx`/`.pptx`/`.xlsx`/born-digital `.pdf` and needs text, load `markitdown-mcp-skill` for the decision tree (markitdown vs `pdf-specialist-skill` vs `image-analyzer-subagent` vs `pdftotext`). The launcher is local-only; privacy details live in the skill + launcher README.

## CodeGraph

CodeGraph is a **tools-only** MCP server (no resources). Call the `codegraph_*` tools directly — never `read_mcp_resource` with a `codegraph://...` URI (it fails; all agent frontmatters set `read_mcp_resource: deny`). If code lookup is needed with no index present, use built-in `Read`/`glob`/`grep`.

**Main session — lightweight lookups only:** `codegraph_search`, `codegraph_callers`/`callees`, `codegraph_impact`, `codegraph_node`, `codegraph_files`, `codegraph_status`.
**NEVER call `codegraph_explore` or `codegraph_context` in the main session** — they flood the context. Spawn an explore agent for exploration.

**Pre-flight initialization:** before spawning any subagent that benefits from CodeGraph, check for `.codegraph/` in the project root. If absent, run `codegraph init -i`, wait for completion, then spawn. If init fails (not installed, non-code project, very large monorepo, read-only mount), proceed without CodeGraph — subagents fall back to grep/glob automatically. In CI/non-interactive contexts (no TTY, read-only mount), skip silently; never block the flow. If the user says "skip codegraph", write `.opencode/codegraph-skipped` to stop re-attempting init.

## Branch Workflow Setup Signal

When a subagent returns `NEEDS_GIT_BRANCH_SETUP: true`, the primary agent handles it — hub-and-spoke (setup subagents only *signal*; they do NOT load the skill or spawn `repo-ops-specialist-subagent` themselves):

1. Load `git-branch-workflow-setup-skill`.
2. Run its §Detection Logic (check for existing release tooling + skip markers).
3. If detection triggers: prompt the user per its §Question Tool Spec, or apply §Non-Interactive Fallback → Skip in headless/CI.
4. If the user accepts: delegate execution to `repo-ops-specialist-subagent` via the Task tool, passing the typed payload from §Delegation Spec.
5. If skipped: write `.opencode/branch-workflow-skipped`.

## Subagent Chaining

Subagents may spawn other subagents via the Task tool, gated by `permission.task` frontmatter. Hub-and-spoke (primary → subagent) is the preferred pattern.

## Commit Conventions

- Follow [Conventional Commits](https://www.conventionalcommits.org/): `type(scope): description`.
- Atomic commits — one logical change each; split migration/ORM model/schema/logic/tests into separate commits.
- Wrap commit body at 72 chars (project commitlint may override, e.g. 120).
- Never mix style/formatting changes with logic changes in one commit.
- For granularity guidance, load `git-semantic-commits-skill`.
